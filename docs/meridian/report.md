# MERIDIAN adaptation: implementation report

This branch extends the existing TypeScript/Express/Playwright engine. It is an implementation checkpoint, not a completed demonstration or a production-readiness claim. The prerequisite PRs #6, #31 and #32 were merged before work began; the isolated branch started at master `49941521d1efc1e28ff18d586c8bb77172ca9416`, whose hosted CI passed. The primary checkout was left untouched.

## What changed

The CLI and HTTP service now construct the same guarded runtime. MERIDIAN selects an application profile containing observed routes, native form destinations, submit labels, token requirements, detectors and evidence masks. Explicit system policy remains authoritative. Version 1 artifacts continue to load; version 2 adds server-bound parameters, explicit select-by-value, structured table extraction and sensitive output metadata. Discovery can record assertions. Its final `done` response cannot invent extracted outputs, and a human repair cannot silently become a complete recorded capability.

The recorder no longer interpolates parameters into CSS. It checks raw and decoded CSS escape forms, discards unsafe strategies and preserves invariant alternatives. Empty values can bind to parameters; ambiguous bindings stop recording. Money inputs use validated decimal strings with integer-cent comparisons. Share selection checks unique option values. Legacy tables can specify data-row selectors independently of named column selectors, including tables with `td` headers.

The asynchronous API returns a run ID and exposes an authorized catalog, history, decisions and evidence. Both OpenAI and MCP tool descriptors are exported; no MCP server was added. A small static dashboard provides invocation, chat, progress and approval controls. Bearer credentials map to caller or operator authority. Public schemas exclude server credentials. The chat executor has only caller-bound invocation, even when the logged-in dashboard user is an operator; it has no approval function. Missing model credentials remain an explicit setup failure.

## Transaction and evidence boundaries

For MERIDIAN clicks, the guard inspects the resolved live control, native form method/destination, current token presence, operator/branch and canonical form/review facts. Profile-defined postings require approval even when the model or artifact calls them reads. The same DOM control and facts are checked again immediately before dispatch. Unknown form submissions and unsolicited browser POSTs are blocked. Role changes, changed facts, accepted aborts, expired decisions and browser closure prevent submission. A single-use approval is bounded to five minutes within a ten-minute run. Human repair keeps the same browser; trusted-event filtering and bounded capture provide evidence, not strong attribution against compromised page scripts.

A filesystem journal reserves requests before a browser opens and records dispatch intent before submission. Records are keyed by caller/request identity and an HMAC over normalized arguments and operator context; raw PII and secrets are absent. Atomic replacement, restrictive permissions, synchronization and a process lock support the one-process demonstration. Same-key retries return the original run across restart. A failure after dispatch without verified completion is terminal `POST_OUTCOME_UNKNOWN`, with no automatic replay, detector retry or unchecked skip. A new key remains a new operation; the target provides no proven exactly-once guarantee.

MERIDIAN evidence uses masked content regions and registered runtime values, redacted result files, and a restricted structured log. Saved DOM evidence contains control structure rather than executable HTML. Unknown pages or failed capture yield an explicit metadata-only warning. Useful synthetic results and approval facts remain in authorized live memory; historical views state that sensitive values are unavailable after restart. All evidence routes authenticate and validate identifiers; UI strings render with `textContent` under a restrictive CSP.

## Evidence and completion limits

The initial baseline passed 106 tests. The expanded suite adds journal restart/tamper checks, authority checks, stale/changed approval cases, a real browser form dispatch test, typed table and option-value tests, private credential-reference tests, and screenshot equality under changes to masked dynamic content. The exact final test count and hosted result belong in the delivery message.

Read-only live probes on September 3–4 verified sign-on, inquiry/member navigation, native token fields, review forms, injected error text, and masked capture through the shared runtime. A down-labelled live Save Changes click was denied without approval. The target contains accumulated state: default shares can be on hold and opening a share requires a minimum deposit. Live error inspection distinguishes business rejections, missing records, supervisor restrictions, session expiry, maintenance and hard server errors. The observed maintenance link returns to the menu; clearing it is not evidence of successful flow recovery.

Azure model access is now configured and verified. Sign-on, member inquiry and member record have genuine model discovery, reviewed artifacts, deterministic replay and sanitized backup evidence. Authenticated API checks cover number/name lookup, ambiguous results without automatic selection, missing-member business outcomes, and same-key request deduplication. See the [evidence manifest](live-evidence.md).

**Still incomplete:** the four write artifacts and their approved deterministic replays; final receipt selectors and posted-result verification; live token rejection; remaining natural errors; and full chat/API/dashboard rehearsal. One approved open-share dispatch reached discovery completion but artifact compilation failed because branch selection was omitted. Its journal correctly remains `POST_OUTCOME_UNKNOWN`; no retry was submitted. Follow-up reads encountered target error pages immediately after sign-on and could not establish the resulting state. Discovery now requires all three login references before sign-on; failed compilation persists a redacted candidate when available and closes the journal with an explicit outcome. The runtime also refuses automated mid-flow re-login.

The design deliberately defers remote CDP, concurrent pools/queues, artifact signing, multi-tenant catalogs, LLM repair, automatic re-login, production encrypted storage/retention and desktop surfaces. Local file access remains trusted. No existing backlog issue should be closed merely because the demonstration implements part of it. Next work requires a usable target session, current share inspection, and separately approved new write operations; UI polish comes after the correctness and safety gates.
